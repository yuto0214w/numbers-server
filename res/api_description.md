部屋の作成と現在の状態の取得は HTTP で行い，実際の対局は WebSocket で進めます。

## 進め方

1. `POST /rooms/new` で部屋を作り，`room_id` を受け取る。
2. `GET /rooms/{room_id}` で盤面とプレイヤーの一覧を取得する。
3. `GET /rooms/{room_id}/ws?v=<バージョン>` で WebSocket に接続し，以降はそちらでやり取りする。

対戦相手には部屋の URL を共有してもらい，同じように 2. から始めてもらいます。

![進め方](procedure.svg)

### バージョンについて

[`/version`](version) は，このサーバーが接続を許可するプロトコルバージョンの一覧を，JSON の配列形式で返します。
クライアントは，開発時点で自身が対応するプロトコルバージョンを保持し，WebSocket に接続する際にそのバージョンを指定します。

プロトコルバージョンは OpenAPI spec の `info.version` (サーバーのバージョン) とは関係がありません。

## WebSocket

やり取りするメッセージは全てテキストフレームの JSON で，`{"t": <番号>, "c": <内容>}` という形をしています。`c` が無いメッセージもあります。
`t` の番号空間は向きごとに独立していて，同じ番号でも意味が違うことに注意してください。

| 向き                                | スキーマ                                         | 番号                                                                                                                         |
| ----------------------------------- | ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| クライアント<br>↓<br>サーバー       | [`PlayerAction`](#models/PlayerAction)           | `JoinTeam` (0)<br>`Resume` (1)<br>`LeaveTeam` (2)<br>`Move` (3)                                                              |
| サーバー<br>↓<br>特定のクライアント | [`Responses`](#models/Responses)                 | `InitialRoomState` (100)<br>`UserCreated` (101)<br>`Authorized` (102)<br>`ActionNotAccepted` (103)<br>`SessionExpired` (104) |
| サーバー<br>↓<br>部屋にいる全員     | [`RegisterRoomEvent`](#models/RegisterRoomEvent) | `MovePiece` (3)<br>`PlayerJoin` (4)<br>`PlayerLeave` (5)                                                                     |

部屋への配信には，イベントを起こしたプレイヤーの `public_id` が `i` として付きます。

また，WebSocket に接続すると，サーバーは接続した時点での部屋の状態を `InitialRoomState` (100) として送ります。

> [!WARNING]
> `MovePiece` では駒の移動元と移動先のみが配信されます。
> 駒が動かされたことによる盤面の変化など，詳細なルールは [`/rule.txt`](rule.txt) を参照してください。

### 参加と復帰

`JoinTeam` に成功すると `UserCreated` で `private_id` と `public_id` が返ります。

- `private_id`: これを `Resume` で示すと認証済みの状態になり，`LeaveTeam` と `Move` が使えるようになります。
- `public_id`: 部屋への配信の `i` やプレイヤーの一覧から自身を特定するために必要です。

#### 猶予切れによる退出 (本人)

接続が切れてもプレイヤーはすぐには消えず，60 秒の猶予があります。その間に繋ぎ直して `Resume` を送れば元のプレイヤーとして復帰できます。
猶予を過ぎていた場合は `SessionExpired` が返るので，`JoinTeam` からやり直してください。

> [!WARNING]
> 同じ `private_id` を用いて `Resume` することで，複数のクライアントから同じプレイヤーとしてゲームに接続できます。
> その場合，猶予が始まるのは，そのプレイヤーのすべての接続が切れたときになります。

#### 猶予切れによる退出 (他のプレイヤー)

猶予を過ぎたプレイヤーが部屋から取り除かれると，`LeaveTeam` のときと同じく `PlayerLeave` が配信されます。`i` はそのプレイヤーの `public_id` です。
猶予切れの確認は 15 秒ごとで，部屋の誰かが操作を送った際にも行われます。

### 操作の結果

失敗した場合は `ActionNotAccepted` (103) が返り，`c` に理由が入ります。

| 理由               | 状況                                       |
| ------------------ | ------------------------------------------ |
| `UNKNOWN_ACTION`   | 未知の `t`                                 |
| `UNAUTHORIZED`     | 未認証                                     |
| `ALREADY_JOINED`   | 既に別のプレイヤーとして参加している       |
| `INVALID_POSITION` | 範囲外の座標                               |
| `INVALID_TURN`     | 自陣の手番ではない                         |
| `INVALID_PIECE`    | 移動元の駒が自陣の駒ではないか，存在しない |
| `INVALID_MOVE`     | 不正な移動                                 |

`Move` または `LeaveTeam` が成功した場合は，個別の応答は返りません。
`i` が自分の `public_id` である部屋への配信 (`MovePiece` / `PlayerLeave`) が届くことで成功がわかります。

### 切断される場合

| コード           | 理由            | 状況                                                                                                                    | 再接続 |
| ---------------- | --------------- | ----------------------------------------------------------------------------------------------------------------------- | ------ |
| 1007 (`INVALID`) | `Invalid Data`  | テキスト，Ping/Pong 以外のフレームを受け取った<br>JSON を [`PlayerAction`](#models/PlayerAction) として解釈できなかった | No     |
| 1013 (`AGAIN`)   | `Server Lagged` | 配信されるイベントの処理がクライアントに対して追いつかなくなった                                                        | Yes    |
